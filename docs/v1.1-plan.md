# BioDex v1.1 Plan — Video, Edge Inference & Tracking

**Theme:** Turn the v1.0 video *foundations* into a full multi-clip workflow, ship a real
edge-inference path (ONNX), and add cross-frame tracking so counts stop double-counting the
same animal.

**Target window:** next minor release after v1.0.0. Backwards compatible — the default
MDv5a + Gradio flow must not regress.

---

## 1. Edge inference (ONNX) — promote the stub to production

Today `core/models/edge.py` has `ONNXDetectorAdapter` / `TensorRTDetectorAdapter` stubs that
raise `NotImplementedError`. v1.1 makes ONNX real.

### Scope
- [ ] Implement `ONNXDetectorAdapter.load()` to load an MDv5a ONNX export via `onnxruntime`,
      honoring available execution providers (CPU, CUDA, DirectML).
- [ ] Implement `predict()` + `build_records()` with letterbox preprocessing and NMS that
      match the PyTorch MDv5a outputs within tolerance.
- [ ] Add a conversion helper: `scripts/export_onnx.py` (torch → ONNX, opset pinned).
- [ ] Register `onnx` in the model registry so `BIODEX_DETECTOR_MODEL=onnx` just works.
- [ ] Provide a tiny fixture ONNX model for CI so the path is tested without large weights.

### Acceptance
- `pip install 'biodex[edge]'` + `BIODEX_DETECTOR_MODEL=onnx biodex batch ...` runs end to end.
- Detections match the MDv5a baseline within an agreed IoU/score tolerance on the LILA sample.
- mypy `--strict`, ruff, and a new `tests/test_edge_onnx.py` all pass.

### Notes / risks
- Keep TensorRT a stub in v1.1 (CUDA-only, hard to CI). Document it as v1.2.
- `onnxruntime` is excluded on macOS arm64 in `pyproject.toml`; keep that guard.

---

## 2. Multi-clip video workflow

v1.0 ships frame extraction + the `biodex video` command for a single file. v1.1 generalizes.

### Scope
- [ ] `biodex video` accepts a directory of clips (and globs), processing each in turn.
- [ ] Per-clip and aggregate summaries (animals, species, frames-with-activity).
- [ ] Configurable frame sampling (every Nth frame / target FPS) with sane defaults.
- [ ] Reuse the batch engine's chunking, cancellation, and ETA progress.
- [ ] Video tab: clip list, per-clip thumbnails, and an export of the combined timeline.

### Acceptance
- A folder of clips produces one combined `VideoResult` set + per-clip breakdown.
- Cancellation mid-folder leaves a consistent partial result (mirrors `BatchResult.interrupted`).

---

## 3. Cross-frame tracking & detection aggregation

Per-frame detection over-counts: the same animal in 30 frames reads as 30 animals. v1.1 adds
lightweight association so video counts reflect *individuals*, not detections.

### Scope
- [ ] IoU-based greedy tracker (no heavy deps) associating detections across adjacent frames.
- [ ] Track objects with stable IDs, first/last frame, peak score, and majority-vote species.
- [ ] "Unique individuals (approx.)" metric alongside raw detection counts.
- [ ] Optional minimum track length to suppress one-frame false positives.
- [ ] Stretch: pluggable tracker interface so ByteTrack/Norfair can drop in later.

### Acceptance
- On a clip where one animal walks across frame, count collapses from N detections to ~1 track.
- Tracking is opt-in/off by default for stills; zero impact on the image batch path.

- [ ] `pytest -m "not slow"` green, with new tests for ONNX, multi-clip video, and tracking
- [ ] `CHANGELOG.md` + `docs/roadmap.md` updated; GitHub Release with attached artifacts

## Sequencing

1. Edge ONNX adapter (unblocks "edge" positioning and is self-contained).
2. Multi-clip video (builds on existing `core/video.py`).
3. Tracking/aggregation (depends on multi-clip frame streams).
4. Desktop packaging verification (parallelizable throughout).

## Out of scope for v1.1

- Acoustic monitoring (BirdNET/Perch) → v1.2
- Local fine-tuning UI → v1.3
- TensorRT production path → v1.2 (CUDA CI required)
